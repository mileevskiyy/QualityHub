# Деплой QualityHub на Render

В корне проекта находится `render.yaml`: он создаёт Docker Web Service и отдельную PostgreSQL в одном регионе. Адрес базы передаётся сервису автоматически. Последующие обновления публикуются после успешных проверок GitHub.

## Тариф и сохранность данных

Конфигурация использует Free для первого демонстрационного запуска. По условиям Render бесплатная база PostgreSQL истекает через 30 дней; бесплатный веб-сервис засыпает после 15 минут без запросов. Это временное демо. Для постоянной ссылки в CV выберите подходящий постоянный тариф базы и сервиса после проверки стоимости в Render. Не рассчитывайте на локальную SQLite в облачном контейнере: файловая система там непостоянная.

## Создание ресурсов

1. Войдите в Render и подключите GitHub с доступом к репозиторию QualityHub.
2. Выберите New → Blueprint и нужный репозиторий.
3. Render найдёт `render.yaml` в ветке main.
4. Проверьте, что создаются только `qualityhub-demo` и `qualityhub-demo-db`, оба на Free, в регионе Singapore. Если имена уже используются вашим другим проектом, сначала задайте уникальные имена в файле и во всех его ссылках.
5. Создайте Blueprint и дождитесь завершения сборки приложения и инициализации базы.
6. Откройте выданный Render HTTPS-адрес веб-сервиса. Конкретный адрес определяет Render; заранее заданного опубликованного URL у проекта нет.

## Первый аккаунт

Чтобы случайный посетитель не создал владельца раньше вас, первый аккаунт требует секретный ключ первоначальной настройки.

1. Откройте веб-сервис в Render → Environment.
2. Найдите сгенерированную переменную `SETUP_KEY` и скопируйте её приватно.
3. На странице настройки QualityHub введите имя, email, собственный пароль и этот ключ.
4. После создания аккаунта ключ не заменяет пароль: последующий вход использует email и пароль. Следующие пользователи регистрируются по приглашениям.

Не добавляйте `SETUP_KEY`, `DATABASE_URL`, пароли и cookies в GitHub, README, публичные сообщения или скриншоты. Пароль аккаунта выбирает и вводит владелец.

## Проверка после запуска

- `/api/health` возвращает JSON со `status: ok`, режимом authenticated и database postgres.
- Можно войти в свой аккаунт и создать проект, тест-кейс, прогон и дефект.
- Перезагрузка страницы сохраняет сессию и записи.
- Проверка повторной отправки отчёта не создаёт дубликат.
- После перезапуска сервиса данные остаются в PostgreSQL.
- В Render Logs нет ошибок соединения с базой.

Проверяйте это до добавления ссылки Live Demo в CV. Для дальнейших изменений достаточно git push и успешных GitHub checks.

## Переменные окружения

`NODE_ENV=production` включает защищённые cookies. `HOST=0.0.0.0` позволяет хостингу принимать запросы. `DATABASE_URL` связывается с PostgreSQL. `SETUP_KEY` генерируется Render. Стандартный `RENDER_EXTERNAL_URL` автоматически добавляется к разрешённым источникам запросов; вручную угадывать домен не нужно. Для дополнительного собственного домена задайте `APP_ORIGIN` его точным HTTPS-адресом.

Публичные подключения к PostgreSQL отключены `ipAllowList: []`; приложение использует внутреннее соединение Render. Не включайте публичный доступ к базе ради устранения ошибки подключения — сначала проверьте регион и переменную DATABASE_URL.

Официальные источники: [Blueprint](https://render.com/docs/blueprint-spec), [ограничения Free](https://render.com/docs/free).
